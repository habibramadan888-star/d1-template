Answers:

- Old employee PIN login page is in `deploy-worker/public/employee-v3.html` as `#loginOverlay`; it is hidden and no longer the normal unauthenticated path.
- Old owner login page is in `deploy-worker/public/index.html` / `index-51-main.js`; `submitCode()` remains disabled for user auth flow.
- Lock icon confusion came from old redirect destinations and fallback login assumptions. The target is now `/`.
- `/` could previously enter owner SPA because static asset fallback served `index.html`; Worker route handling now intercepts `/` first.
- `employee-v3.html` is no longer a formal login path; it is a legacy alias to `/employee`.
- `index.html` is no longer a formal login path; it is a legacy alias to `/owner`.
- `unified-login.html` is no longer a formal independent entry; it is a legacy alias to `/`.
- Paths converted to alias/redirect: `/login`, `/unified-login.html`, `/employee.html`, `/employee-login`, `/staff-login`, `/owner-login`, `/admin-login`, `/employee-v3.html`, `/employee-v2.html`, `/index.html`, `/index-51.html`.
