## Findings

1. “分析”入口丢失 because the HTML nav removed the `navAnalysis` button, while `showOwnerAppShell()` and `switchView()` still supported `analysis`.
2. The configuration that removed it was the owner primary nav in `deploy-worker/public/index-51.html` and synced `deploy-worker/public/index.html`.
3. This was a regression from the earlier compact mobile navigation change that reduced visible tabs and hid clients.
4. `signal is aborted without reason` came from timeout aborts in `apiFetchWithTimeout`, not from a D1/API write.
5. The UI previously treated timeout/AbortError as a hard data-load error and displayed it to the user.
6. Duplicate fetch protection existed, but stale requests were not sequenced strongly enough for async TTLock hydration.
7. API returns arrears data with a first-page limit; the UI now consumes final source aliases and employee feedback aliases.
8. readonly_admin did not cause request aborts; readonly scope remains an action visibility/write guard concern.
