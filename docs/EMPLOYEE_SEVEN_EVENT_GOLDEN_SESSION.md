# Employee Seven-Event Golden Session

Run the reusable local acceptance harness with one command:

```powershell
npm run verify:employee-golden-session
```

The command creates a fresh temporary local Wrangler environment, applies only the repository's local bootstrap SQL, adds the canonical archive columns to that temporary database, seeds a sanitized TTLock snapshot in temporary local KV, creates authenticated STAFF and Manager sessions, and exercises the formal Worker HTTP routes. It never uses `--remote`, production D1/KV, a production hostname, or the live TTLock API. The temporary directory is removed in `finally` blocks after each phase.

## Coverage

The fixed manifest contains 16 scenarios:

- Rent: cash full-paid, bank short-paid, and cash excess.
- Arrears Payment: cash formal-cloud and bank legacy-manual.
- Deposit In: cash and bank.
- Deposit Out: cash and bank.
- Checkout: clear and left-with-arrears.
- Expense: cash AED 99 and bank AED 500 without `evidence_ref`.
- Bed Transfer: paid cash, paid bank, and waived.

Every case has a stable scenario session ID and Entry ID, fixed input, fixed expected canonical/Finance/Owner/Arrears/Todo effects, and an explicit TTLock-call expectation. The expected Finance oracle is a hand-authored constant and is not generated by production projection code.

## Acceptance phases

1. Aggregate validate-only returns 16 Entry-ID-associated results. A negative fixture removes one Expense description and proves only that Expense fails while all 16 drafts remain present and formal writes remain zero.
2. All 16 scenarios are written through `POST /api/employee/entry`, then read through Owner History, Finance, Arrears, and Today Todo routes. Repeating the same writes must add zero anchors and zero Finance delta.
3. A fresh environment writes the first eight entries, logs out, proves the protected route returns 401, logs in again, revalidates all 16, identifies eight already persisted and eight pending, and writes only the missing eight. Final archive cardinality must be 16 with no duplicate anchor identities.
4. Auth/draft recovery contracts prove 503, 422, malformed aggregate responses, and non-string error codes retain all drafts and do not redirect. Only an explicit authentication 401 redirects.

The fixed snapshot keeps external TTLock, OAuth, lock-list, identity-card, and Exit Event live calls at zero. Runtime diagnostics also assert one aggregate archive read and one `entries_json` parse for the 16-entry request.

## Reports

Successful execution prints the required compact PASS lines and writes a JSON report to:

```text
%TEMP%\homelink-employee-seven-event-golden-session-report.json
```

The JSON includes validation, identity association, write/retry, partial-resume, Finance oracle, Owner projection, resource-count, and safety results. Because the evidence database is temporary, the report contains results only and no reusable authentication material.
