# Receivables Source Of Truth

Status: P0-008C local/staging rehearsal source-of-truth definition. This is not production authority.

| Concept                  | Source / Future Table                                        | Authority Rule                                                                               | Current Legacy Equivalent                             | Notes                                                     |
| ------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------- |
| receivable               | `receivables`                                                | One billable obligation with amount, paid, outstanding, status, due date, and audit anchors. | `arrears` / `arrear_tasks` / rent transaction context | Future authority only after migration and reconciliation. |
| receivable_event         | `receivable_events`                                          | Append-only lifecycle event for create, allocate, adjust, void, writeoff, or correction.     | `audit_logs`, `entry_events`, staff notes             | Mutations must be auditable.                              |
| payment_allocation       | `payment_allocations`                                        | Links a payment source to a receivable with `allocated_fils`.                                | Implicit links via transaction/task text              | Repayment must reduce a selected/open receivable.         |
| adjustment               | `receivable_adjustments`                                     | Owner-approved non-cash change to outstanding balance.                                       | Manual staff/owner notes                              | Must not be recorded as cash received.                    |
| rent due                 | `receivables.amount_fils`                                    | Server-generated amount in integer AED fils.                                                 | Rent formula / employee entry due                     | Frontend due is not authority.                            |
| short pay                | `receivables.outstanding_fils` + allocation                  | Paid amount less than due leaves outstanding.                                                | Arrear task or free-text follow-up                    | Not an implicit discount.                                 |
| outstanding balance      | `receivables.outstanding_fils`                               | `amount_fils - paid_fils - approved_adjustments`, never below zero.                          | `remain`, `arrear_amount - actual_received`           | Legacy fields are comparison only.                        |
| arrears                  | Open/partial receivables due on or before business date      | Sum active outstanding receivables.                                                          | `arrears` / `arrear_tasks`                            | Future dashboard authority.                               |
| repayment                | `payment_allocations`                                        | Allocates payment to open receivable and reduces outstanding.                                | Arrears payment transaction                           | Must retain source payment id.                            |
| overpayment              | Allocation warning / separate state                          | Receivable closes; extra amount requires separate handling.                                  | Negative remaining or manual review                   | Must not create negative arrears.                         |
| refund                   | Deposit ledger / explicit adjustment                         | Refund does not reduce rent receivable unless approved offset exists.                        | Deposit refund transaction                            | Deposit is separate from rent receivable.                 |
| void impact              | `voided_at` / void event                                     | Voided payment does not reduce active outstanding; original rows remain auditable.           | Soft-delete / void behavior                           | No hard delete.                                           |
| deposit handling         | Deposit ledger, not rent receivable by default               | Deposit can offset rent only through approved adjustment.                                    | `deposit_ledger` / deposit transactions               | Prevents silent rent debt hiding.                         |
| monthly rent config      | Future effective-date rent config                            | Amount is locked at receivable creation time.                                                | List rent / TTLock remark parsing                     | Existing receivable does not drift when config changes.   |
| due date                 | `receivables.due_date`                                       | Dubai business-date due date.                                                                | Legacy date fields                                    | Needs timezone policy before production.                  |
| overdue date             | `due_date < businessDate`                                    | Computed from active outstanding receivables.                                                | Legacy arrears status/date                            | Future dashboard authority.                               |
| employee entry relation  | `source_type`, `source_id`, events                           | Employee write creates payment and receivable/allocation plan after backend validation.      | `/api/employee/entry` legacy write                    | Production still legacy.                                  |
| handover relation        | handover commit rows -> transactions/receivables/allocations | Atomic handover should accept rows and receivable effects together.                          | staging handover endpoint                             | Production handover cutover remains NO-GO.                |
| dashboard due today      | receivables totals                                           | Sum active outstanding receivables due today.                                                | dashboard legacy due logic                            | Staging shadow only.                                      |
| dashboard overdue amount | receivables totals                                           | Sum active outstanding receivables due before business date.                                 | legacy arrears/task aggregation                       | Staging shadow only.                                      |
| dashboard arrears total  | receivables totals                                           | Sum active open/partial outstanding balances due on or before business date.                 | `arrears` / `arrear_tasks`                            | Production blocked by P0-008/P0-006.                      |

Rules:

- `amount_fils`, `paid_fils`, `outstanding_fils`, allocation amounts, event amounts, and adjustment amounts are INTEGER AED fils.
- Legacy arrears are compatibility and comparison inputs only.
- Frontend totals are never accounting authority.
- Voided payments do not reduce active outstanding totals.
- Repayment must allocate to a receivable.
- Every mutation needs audit/event evidence.
