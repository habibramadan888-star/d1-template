# Backend Totals Source Of Truth

Scope: P0-003B rehearsal. This document defines the target source-of-truth rules for backend totals without changing current production API output.

| Cash total               | `transactions`                                  | Accepted cash income rows: rent, deposit in, arrears paid, transfer fee                   | Voided rows, invalid rows, cash outflows           | Parse legacy AED value to integer fils; future source is `amount_fils` | Exclude rows with `voided_at` unless `includeVoided=true` | Cash total is cash inflow, not cash handover after refunds/expenses.   |
| Bank transfer total      | `transactions`                                  | Accepted bank income rows                                                                 | Voided rows, invalid rows, bank outflows           | Integer fils                                                           | Exclude voided by default                                 | Count bank rows with positive amount separately.                       |
| Gross received           | `transactions`                                  | All accepted income rows before refunds/expenses                                          | Voided rows, refund/expense outflow rows           | Integer fils                                                           | Exclude voided by default                                 | Gross received = cash income + bank income.                            |
| Rent received            | `transactions`                                  | Rent category rows with positive accepted payment                                         | Voided rows, invalid rows                          | Integer fils                                                           | Exclude voided by default                                 | Legacy may use `type='R'`.                                             |
| Deposit received         | `transactions`, future `deposit_ledger`         | Deposit collection rows                                                                   | Voided rows, deposit refund rows                   | Integer fils                                                           | Exclude voided by default                                 | Deposit received is not profit; dashboard must keep it separate.       |

| Dashboard monthly income | `transactions`, future `payments`               | Income rows in Dubai business month, excluding deposits if the KPI means operating income | Voided rows, refund/expense rows                   | Integer fils                                                           | Exclude voided by default                                 | KPI definition must be explicit: gross received vs operating income.   |

| History row amount       | `transactions`                                  | The preserved row amount for display/audit                                                | None for audit; active view excludes voided        | Integer fils plus display string                                       | Active view excludes; audit may include                   | History display must not become the authority for summary totals.      |

## Authority Rules

1. Voided records are excluded from active totals by default.
2. `includeVoided=true` is only for audit and discrepancy reporting.
3. Frontend submitted totals are never accounting authority.
4. All authoritative totals must be computed in integer AED fils.
5. Current legacy decimal fields are compatibility input only.
6. Invalid money values must produce structured errors, not silent zero.
7. Backend totals can be switched to production only after P0-001 integer write strategy, P0-002 atomic handover, and P0-008 receivables are reconciled or explicitly scoped.
